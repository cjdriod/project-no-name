A good personal website is not a resume copied onto web pages. Each page should answer a different question:

Home: "Why should I keep reading?"
About: "Who are you and how do you work?"
CV: "What exactly can you do?"

Many developers repeat the same skill list on every page, which creates redundancy. Instead, let each page serve a distinct purpose.

Home page

Keep it concise. Visitors decide within seconds whether to continue.

Show:

Short introduction
Current role
4–8 strongest skills
Call-to-action

Example:

Full-Stack Software Engineer specializing in scalable backend systems, cloud architecture, and modern web applications.

Core Expertise
✓ Java (Spring Boot)
✓ Node.js & Express
✓ React
✓ AWS & Azure
✓ Microservices
✓ CI/CD

Then support those strengths with the technologies you use.

For example:

Backend Architecture
Java • Spring Boot • Hibernate • Node.js • Go

Cloud-native Applications
AWS • Azure • Docker • Serverless

Frontend
React • Vue • Angular • Tailwind

Data
PostgreSQL • MySQL • MongoDB • SQL Server


This communicates capabilities first, technologies second.

A simple content strategy
Page	Goal	Skills shown
Home	Make a strong first impression	Top 5–8 signature skills only
About	Explain what kind of engineer you are	Grouped capabilities with representative technologies
CV	Comprehensive technical reference	Complete categorized skills list

This progression mirrors how hiring managers and clients typically evaluate candidates: they first want to know what you're known for, then how you work, and finally the full breadth of your technical experience.

which section to use highlight?

I'd use Highlights in both the Home and About pages, but for different purposes.

Home page: Technical highlights

The home page should answer, "What are you best at?"

Keep it short—around 4–6 cards or bullet points.

Example:

What I Do
Backend Engineering — Java, Spring Boot, Node.js
Cloud Architecture — AWS, Azure, Serverless
Frontend Development — React, Vue
Microservices & APIs — RESTful services, event-driven systems
DevOps — Docker, CI/CD, GitHub Actions

This gives visitors an immediate understanding of your expertise without overwhelming them.

About page: Professional highlights

The About page answers, "What kind of engineer are you?"

Instead of focusing on technologies, highlight your strengths and working style.

For example:

Highlights
5+ years building enterprise web applications
Experience across backend, frontend, and cloud platforms
Passionate about scalable system design and clean architecture
Strong advocate of automated testing and CI/CD
Comfortable collaborating in Agile teams

Then follow with your grouped technical skills:

Backend Engineering
Java • Spring Boot • Node.js • Python • Go

Cloud & Architecture
AWS • Azure • Microservices • Serverless

Frontend
React • Vue • Angular

Data
PostgreSQL • MySQL • MongoDB

DevOps
Docker • Git • CI/CD • Linux
CV page: No "Highlights" section needed

The CV is meant to be comprehensive. Recruiters expect to see everything, so organize your skills into categories such as Languages, Backend, Frontend, Cloud, Databases, DevOps, Testing, and Monitoring.

// src/components/StaticQRCode.astro
import QRCode from 'qrcode';

interface Props {
  data: string;
  size?: number;
}

const { data, size = 200 } = Astro.props;

let qrDataUrl = '';
try {
  qrDataUrl = await QRCode.toDataURL(data, {
    width: size,
    margin: 2,
    color: {
      dark: '#000000',
      light: '#FFFFFF'
    }
  });
} catch (error) {
  console.error('Failed to generate QR code:', error);
}
